# Политика безопасности

## Безопасное использование

BreakCurl один раз отправляет исходный запрос, а затем может отправить до 200 последовательных проверочных запросов `POST`, `PUT`, `PATCH` или `DELETE`. Профили по умолчанию ограничены 15–120 кейсами. Используйте инструмент только для систем, которые вам разрешено тестировать, и только с disposable-данными, которые можно безопасно изменить или восстановить.

Перед запуском BreakCurl показывает очищенный целевой адрес, профиль, точное количество запросов и категории проверок. Интерактивный режим требует подтверждения. Неинтерактивный запуск требует `--allow-mutation`. `--dry-run` всегда выполняется без HTTP-запросов.

Профили `security` и `full` могут отправлять исходное валидное тело без credentials или с невалидными credentials. Если endpoint уязвим, такой запрос может выполнить бизнес-операцию. Для auth-probes используйте непродуктивное окружение, отдельную тестовую сущность и план восстановления. `--expect-auth` означает, что только `401/403` считается доказанным auth-отказом.

Security payloads используют ограниченные неисполняемые маркеры. BreakCurl не выполняет brute force, SSRF, race/load, извлечение данных или автоматическую эксплуатацию найденного поведения.

BreakCurl разбирает входной cURL как данные и не выполняет его через shell. Неподдерживаемый shell-синтаксис и неподдерживаемые возможности cURL отклоняются до отправки запросов.

Чувствительные headers, query-параметры, JSON-поля, известные credential values, JWT и private-key patterns маскируются в создаваемых файлах. Ответы API не записываются: отчёт содержит только status, метаданные и fingerprint структуры. Маскирование не заменяет краткоживущие тестовые credentials и минимальные права.

BreakCurl работает локально: у него нет аккаунтов, телеметрии или загрузки данных в облако.

## Поддерживаемые версии

Исправления безопасности предоставляются для последней опубликованной версии.

## Сообщение об уязвимости

Не добавляйте действующие учётные данные, персональные данные или production payload в публичные Issues. Отправьте владельцу проекта минимальный и очищенный пример через приватный GitHub Security Advisory. Укажите затронутую версию, влияние, шаги воспроизведения и ожидаемую защиту.
